# Barr-C 2018 compliance — IS11 firmware (`app_program/`)

Clean-up of 22 Nov on top of the 18 Nov firmware.  **The car's logic is
unchanged**: every change below is either layout only (same machine code)
or a restructuring that was checked to give exactly the same outputs (see
*Verification*).

Scope: the team's code in `app_program/`.  `kernel/`, `lib/`, `device/`,
`include/` and `build_make/` come from the course template / Pico SDK and
are not modified.

## How it was checked

| Check | Tool / command | Result |
|---|---|---|
| Braces around every `if` / `else` / loop body | `clang-tidy -checks=readability-braces-around-statements` | 0 findings (was 38) |
| No bitwise operations on signed values | `clang-tidy -checks=hicpp-signed-bitwise` (positive literals as shift counts allowed) | 0 findings (was 14 real ones) |
| Functions at most 100 lines | `clang-tidy -checks=readability-function-size`, `LineThreshold=100` | 0 findings (was 6) |
| Lines at most 80 characters | every `.c`/`.h` line, tabs counted as 8 columns (GitHub's default) | 0 lines over 80 (was 759) |
| Parameterised macros only where a function cannot do the job | `grep '#define NAME('` | 5 left, each justified below (was 18) |
| `goto`, `switch` without `default`, headers without include guards | grep / clang-tidy | none |
| Build warnings | `make SMP=0 NET=lwip MQTT=1` and `TEST=1` | 0 warnings |
| Strict warnings | the same build with `-Wall -Wextra -Wshadow -Wundef -Wmissing-prototypes -Wstrict-prototypes -Wformat=2` | in `app_program/`: only `usermain` (see deviations) |

clang-tidy was run with the firmware's own compile flags (taken from
`make -n`), `-DAPP_TEST=1 -DAPP_US_DIAG=1` so the test and diagnostic code
is checked too.

## Documented deviations

| Rule | What we do | Why |
|---|---|---|
| Indentation with 4 spaces, no tabs | Tabs | Course template style (kernel, template files); kept so the whole project is consistent |
| Brace placement | K&R (`if (x) {` on one line) | Course template style |
| `stdint.h` fixed-width types | µT-Kernel types `W`, `UW`, `H`, `UH`, `B`, `UB` | Required by the µT-Kernel API; they are fixed-width typedefs |
| Function prototypes | `usermain` has none | Template entry point, called by the kernel |
| Line width | Generated files `*.pio.h` exceed 80 characters | Generated by `pioasm`; regenerated, never edited |
| Parameterised macros | `APP_STATIC_ASSERT` (declares a type), `TLM_FIELD` / `TLM_BIT` (paste the field name with `##`), `NOTES` (needs the array type for `sizeof`), `TEST_CHECK` (reports the caller's `__FILE__` / `__LINE__`) | A function cannot do any of these; each has a comment saying so |

## What changed

* **Braces**: 38 one-line `if` / `while` bodies now have `{ }`.  An
  `if / else if` in `line_sense.c` gained its final `else`.
* **Signed shifts**: `app_asr()` (in `app.h`) does an arithmetic shift
  right on the unsigned magnitude.  Used by the IMU low-pass filter
  (`task_imu.c`) and the LSM303 driver (`drv_lsm303.c`, which also builds
  the signed 16-bit value without an out-of-range cast).  Unsigned casts
  were added where a `UB`/`UH` was promoted to `int` before a shift, and
  where the kernel's signed `GPIO_*` / `PWM_*` bits are combined.
* **Macros to functions**: `APP_ABS` → `app_abs()`, `APP_CLAMP` →
  `app_clamp()`, `APP_BARCODE_MAP` → `app_barcode_map_pack()`, `CHECK` →
  `app_check()`, `SERVO_IDX_TO_DEG` / `SCAN_DEG_TO_IDX` →
  `servo_idx_to_deg()` / `servo_deg_to_idx()`, `LOST_DEG_TO_MM` →
  `lost_deg_to_mm()`, `TEST_INIT` / `TEST_SUMMARY` → `test_init()` /
  `test_summary()`.  Register-address macros (`I2C0_REG()`,
  `PWM_DIV_REG()`, `US_REG()`) became plain constants.  Every caller of
  `app_abs` / `app_clamp` was checked at compile time to pass `W`, `INT`
  or `H`, which all fit a `W` unchanged.
* **Long functions split** into named steps (same statements, same
  order):
  * `line_task` (494 lines) → `line_start`, `line_cycle_begin`,
    `line_barcode_travel`, `line_consume_samples`, `line_barcode_sample`,
    `line_count_bars`, `line_reader_result`, `line_cross_sample`,
    `line_levels`, `line_lift_check`, `line_early_hold`, `line_steer`,
    `line_found`, `line_lost`, `line_fan_search`; shared state in
    `LINE_CTX` on the task's stack.
  * `imu_task` (217) → `imu_learn_level`, `imu_read`, `imu_lift_step`,
    `imu_hump_step`, `imu_motion_event`; state in `IMU_CTX`.
  * `scan_task` (211) → `scan_watch_step`, `scan_hump_pause`,
    `scan_glance`, `scan_bypass_step`, `scan_pass_watch_step`,
    `scan_guard_step`, `scan_idle_step`; state in `SCAN_CTX`.
  * `bc_reader_feed` (125) → `bc_adapt_levels`, `bc_edge`,
    `bc_state_step`, `bc_abort_long_read`.
  * `run_follow`, `scan_profile`, `ctrl_task`, and the test / bench /
    diagnostic functions (`subsystemN_test`, `bench_ir`, `bench_imu`,
    `diag_round`).
* **Line width**: trailing comments moved above their line, long comments
  re-wrapped, long strings split into adjacent literals (the compiler
  joins them), long expressions broken after an operator, one statement
  per line.

## Verification (logic unchanged)

* **Build**: 0 warnings, normal and `TEST=1` builds.
* **Layout-only changes give identical machine code**: after the line
  wrapping, every object file's code and data, and the whole `.uf2`, are
  byte-for-byte identical to the build before it.  Brace fixes likewise
  compile to identical objects.
* **Host tests** (`sh tools/host_test/run.sh`): 81 of 81 checks pass;
  the complete output of the unit tests, the motion simulation, the
  controller simulation, the sensor-bench simulation and the MQTT codec
  self-test is identical to the 18 Nov code.
* **Task-level traces**, before and after, identical line for line:
  * `simline` (the real `line_task`): all 10 scenarios, every 20 ms line
    error, flags, navigation message and log line;
  * `simimu` (new, the real `imu_task`): level learning, a hump, a lift,
    a tilt and an I2C failure, with noisy (negative) readings;
  * `simscan` (new, the real `scan_task`): watch, hump pause, alert,
    sweep, profile, pass watch, rescan, guard and bench pings.
* **`app_asr`** compared with `>>` for 6.2 million values: no
  difference.  **LSM303 conversion** compared for all 65 536 register
  values: no difference.

## Found while checking

1. **Bypass guard (not changed on this branch).**  In `scan_task`'s
   bypass state, `confirm` is reset to 0 at the start of every pass
   through the loop, so the guard's "2 readings in a row under 120 mm"
   (`++confirm >= 2`) can never be reached and `OB_CLEARANCE_LOST` is
   never sent.  This branch keeps the 18 Nov behaviour exactly; the fix
   is on the `barr-c-compliant+bypass` branch.
2. **`simline right` updated.**  The scenario was written before the
   16 Nov C+R early hold and expected a right correction straight away.
   Since 16 Nov the error is held at 0 for 45 mm when C and R are both
   black, so it failed.  The simulation feeds a fixed sensor pattern (the
   car does not turn), so this was an out-of-date test, not a fault on
   the car: the 22 Nov track video shows the 18 Nov code taking the 90°
   right corner and the S-bends.  The expectation now matches the 16 Nov
   rule, and all 10 line scenarios pass.
